How it works — no magic, no fake data

  1. Entropy: length × log₂ of the character pool actually used (26 per letter case, 10 digits, 32 symbols). A random 16-character mixed password is ~105 bits.
  2. Pattern checks: the password is tested against a built-in list of 206 widely published top-passwords (including leet-speak like P@ssw0rd), keyboard walks (qwerty, 1qaz), sequences (abc, 123), repeats, and years.
  3. Predictability model: a character-trigram model trained on that same 206-password list scores how much the password "looks like" a common one. Small and honest — it is a teaching-size model, not a breach database.
  4. Crack time: average guesses = 2^(effective entropy − 1), divided by a stated rate. Online: 100 guesses/sec (throttled login). Offline: 10 billion/sec (fast hash on a GPU).

Honest limits

  • The common-password list is a small sample, not a breach database — a password can be "not found here" and still be leaked somewhere.
  • Entropy assumes characters are random. A "strong" score does not protect a password that is reused, phished, or stored in plaintext by a website.
  • Use a different password for every site, and turn on 2-step verification wherever it is offered.
